# vp415-service-guide

A service guide for the Philips VP415 Domesday LaserDisc player.

## 📖 Read it here: **<https://simoninns.github.io/vp415-service-guide/>**

The site is the point of this repository — everything below is how it gets built.

---

## What this is

The Philips VP415 is a LaserVision ROM disc drive: a 12-inch videodisc player with a SCSI
interface, built in 1986 so a computer could drive it. It is the player at the heart of the
**BBC Domesday Project**.

This repository holds a repair and servicing reference for that player, built around the original
Philips service manual — 197 sheets covering technical data, the twenty-six plug-in modules A to Z,
circuit descriptions, parts lists, the diagnostic software and its error codes — together with
material the manual does not have: firmware dumps with checksums, the F-code command set, bench
calibration guides and repair case studies.

**It is a work in progress.** The site structure is complete and every page exists, but most pages
are still placeholders naming the sources their content will be built from. See
[planning/implementation-plan.md](planning/implementation-plan.md) for what is done and what is next.

## Repository layout

| Path | What |
| --- | --- |
| `docs/` | The site: one markdown page per topic, with each section's assets beside it |
| `docs/**/assets/originals/` | The archival scans and photographs — **committed, the single copy of each file** |
| `docs/**/assets/web/` | Web derivatives — gitignored, regenerated by `just derive` |
| `planning/` | The implementation plan, the source manifest, and the CSVs that drive the tooling |
| `tools/` | The migration and asset-derivation scripts |
| `mkdocs.yml` | Site configuration and the explicit navigation tree |

There is exactly one copy of every source file in this repository. Files were `git mv`d out of the
original unsorted material into their final home under `docs/`, and every move is recorded in
[planning/migration-log.csv](planning/migration-log.csv) so provenance survives the rename.

The archival originals are committed but **not published**: at 918 MB they would take the rendered
site past the 1 GB ceiling GitHub Pages puts on a published site. The site serves the derivatives
instead, and for every schematic, photograph and scope trace the lightbox image is the scan at its
native resolution. Clone the repository if you want the lossless files.

## Building it locally

Everything runs inside the Nix dev shell, which pins MkDocs, the theme, the plugins and the image
tools:

```sh
nix develop          # enter the shell
just                 # list the available tasks
just serve           # derive the web assets, then serve with live reload
just build           # strict build into site/
just check           # strict build plus an offline link check
```

Or without entering the shell: `nix develop -c just serve`.

`just derive` regenerates `docs/**/assets/web/` from the committed originals. It hashes each source
and skips unchanged files, so a warm re-run takes about two seconds; from clean it takes under a
minute. `nix build .#site` produces the whole site as a reproducible derivation.

## Deployment

Every push to `main` builds and publishes the site through
[.github/workflows/deploy.yml](.github/workflows/deploy.yml): `just derive`, then
`mkdocs build --strict`, then GitHub Pages.
